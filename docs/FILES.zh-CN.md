# 桌面文件传输

[客户端 0.1.21](https://github.com/wanghao9103/farsail/releases/tag/client-v0.1.21) 提供 Ubuntu 与 Windows 桌面的双向单文件传输，Ubuntu 包包含 x64 与 ARM64。不代表更早的安装包具备相同能力。两端客户端与协调服务需一起升级：协调服务必须接受 Linux 文件能力，并保持文件批准与屏幕共享独立。Windows 代码、NTFS、原生查看器及安装/重启/重装/卸载 CI 检查已通过；原生文件对话框尚未在物理 Windows 机器完成验收；0.1.21 的三平台签名安装包已公开发布。

[客户端 0.1.28](https://github.com/wanghao9103/farsail/releases/tag/client-v0.1.28) 已从 `11a75bbfe5a49fd2665c98b34bb3d7c817cd255c` 发布。[正式工作流](https://github.com/wanghao9103/farsail/actions/runs/39365699777)、公开包签名和固定更新清单逐字节核验通过。两端均需升级后使用远控文件粘贴；物理双机剪贴板/Explorer 验收仍待完成。

## 远控会话内复制粘贴（0.1.28）

两端均使用包含此功能的客户端时，批准一次**远程控制**即可传输文件，无需另建 Files 连接或再次确认每个文件。设备面板的独立文件按钮合并进远程控制；仅支持文件接收的设备仍保留独立文件入口。

1. 连接远程控制，在远端打开目标文件夹并保持该窗口在前台。
2. 在本机文件管理器复制普通文件，回到远程画面按 **Ctrl+V**；也可点击工具栏的**传输文件**选择文件。
3. 一次最多 32 个普通文件，按顺序传输并显示进度。全部通过完整性校验后，远端写入文件剪贴板并发送粘贴。显示成功说明粘贴操作已发出，文件管理器的后续复制或同名文件处理仍由系统完成。

本机支持 Windows 文件剪贴板或 Ubuntu URI 文件列表；目标目前为 Windows。文件夹、链接、网络 URI、远端复制回本机暂不支持。只读会话不能传文件；旧端未声明能力时按钮不可用。接收先写入原生私有临时目录，不展示保存对话框；目录保留至应用退出，避免会话结束时删除系统仍在复制的来源。异常退出可能遗留临时文件。目标前台窗口变化、授权结束或输入暂停时停止自动粘贴。没有复制本机文件时，Ctrl+V 保持远端原有剪贴板粘贴行为。

## 独立文件连接的发送与接收

以下步骤适用于客户端 0.1.23 起的版本。旧版 0.1.22 使用独立的**允许接收文件**开关，每次重启应用后关闭；升级后使用下述统一设置和验证后恢复。

1. 两台电脑均登录并首次添加一次本机，保持应用运行。接收方选择本机设备或打开“共享与设置”，开启**允许远程连接**。Windows 同时允许屏幕与文件请求，Ubuntu 仅允许文件请求，无需单独开启文件接收。首次默认关闭；选择会保存，普通重启后仅在同一登录/设备和所需原生服务验证通过时恢复。手动关闭后保持关闭，退出登录或身份变更清除开启偏好。
2. 发送方在**我的设备**中选择在线接收设备；提供独立文件入口的设备可点击**文件传输**。也可在**远程连接 → 连接他人电脑**选择**仅传输文件**发起请求。对方未允许远程连接、离线或设备被停用时不能接收请求。仅发送文件时，发送方不必允许本机被远程连接。
3. 接收方点击**允许文件传输**。每次文件连接都需要明确批准，包括已开启远程值守的同账号设备。这只授予文件权限，不授予屏幕查看或鼠标键盘控制权限。
4. 连接后进入**文件传输**，点击**发送文件**。原生打开对话框选择一个本机普通文件；对方看到文件名与大小，本机路径保留在 Rust 中。取消对话框不会产生传输任务。
5. 接收方看到文件申请后选择**保存到…**或**拒绝**。原生另存为对话框为该文件选择确切目标；取消对话框会保留待处理申请，选择目标前不创建文件。仅批准连接不会自动写入文件。
6. 连接双方均可发送文件。记录显示等待接收、进度、完成、拒绝、取消或失败原因；完成后不会自动打开或执行文件。**取消传输**可停止待对方接收的发送任务或正在进行的任务，**结束连接**撤销本次连接。

客户端 0.1.30 的独立文件页区分“等待对方批准文件连接”“待你批准文件连接”和“已批准，等待建立文件连接”。接收方可点“查看请求”进入待批准列表；发送方等待期间可“取消请求”，批准后尚未建立连接时可点“建立连接”。暂无文件连接时，“选择设备”打开设备页。页头“刷新文件状态”更新连接与传输记录；连接列表与记录区可分别滚动，连接按钮可用 Tab 聚焦、Enter 或空格选择。

0.1.23 起关闭主窗口后，有可用托盘时隐藏到托盘，否则最小化，不会停止文件传输。重新打开界面处理批准和保存位置；从托盘或窗口菜单明确退出应用会停止传输。旧版 0.1.22 保留原有关窗行为。

跨账号时，创建权限为**仅传输文件**的一次性邀请码，把接收设备 ID 和邀请码交给申请方；目标设备仍须批准连接。邀请码不能授予屏幕或控制权限。参见[客户端使用](CLIENT.zh-CN.md)与[授权 API](API.zh-CN.md)。

## 本机范围与完整性

独立文件连接使用 `files` 授权与 `Channel::File`。客户端 0.1.28 也允许 `control` 会话使用文件通道，沿用同一身份、连接和短租约；`view` 仍不能使用文件通道。统一远程开关仅在原生传输与文件处理可用时声明 `can_files=true`；Windows 通过屏幕检查后还会开启 `can_host`，Ubuntu 始终保持 `can_host=false`。协议能力与授权仍分别校验，界面不再提供两个开关。关闭远程连接先停止本机接入的屏幕与文件会话，再尝试更新服务器能力；退出登录、停止传输或授权失效也会停止本机操作，迟到的文件对话框结果不能恢复已结束会话。

对方不能浏览本机目录，也不能指定任意本机路径。每次原生打开对话框只授权读取所选的一个源文件，每次原生另存为对话框只为一个已申请的文件指定保存目标。React 仅获得会话/任务编号、显示名称、大小、进度和错误，不获得完整本机路径、签名密钥、账号/设备令牌或授权凭据。

接收方以目录能力句柄打开用户所选的父目录，并在其中独占创建随机 `.farsail-part-*` 文件。检查连续偏移、声明大小和最终 SHA-256 后，以原子且不替换目标的硬链接发布已验证文件。目标已有文件、目录或符号链接时保存失败，包括接收批准后才创建的目标；没有覆盖功能，也不会降级到削弱规则的重命名或复制方式。正常清理时，取消、断开或校验失败会释放接收器并删除临时文件。

请选择支持硬链接的文件系统，例如合适的 ext4 或 NTFS 目标。FAT/exFAT 等不支持硬链接的文件系统无法发布接收文件，会保存失败而非静默改用不安全方法。强制杀进程或断电可能留下 `.farsail-part-*` 文件；确认 FarSail 没有正在传输后，仅检查该任务选定的目标目录，应用不会递归扫描并删除无关文件。

## 连接方式与限制

文件连接复用已有 iroh 端点身份与路径发现状态，先为 P2P 直连保留最多 3 秒窗口。已知 IP 时先直接拨号；只有中继地址时，可先建立可信连接用于发现与穿透信令，但在文件授权与负载发送前仍等待直连升级。已有可用直连立即使用，窗口内未能直连才允许中继文件负载；回退不重复等待第二个窗口。高级设置中显式选择的**始终通过中继连接**仍有效。中继要求正常可信 HTTPS/TLS 校验，不关闭证书检查。面板展示实际选中的直连或中继路径，不保证所有网络都能直连。该策略不会重启或替换已有屏幕连接。

协议每块最多 64 KiB，收到该块确认后再发送下一块。同一应用内所有发出的文件会话共享固定 4 MiB/s 文件带宽预算；这是文件协议预算，不是链路速度、屏幕加文件总流量或网络开销保证。单文件最大 64 GiB。发送方先检查源文件内容，再在发送过程中复核；接收方在报告成功前检查完整 SHA-256。大文件在显示申请前需要时间计算摘要。

独立文件连接每次选择一个普通文件；远控粘贴支持最多 32 个文件。共同限制：不支持递归目录、远端目录浏览、覆盖、断线暂停/续传、选择性压缩或自动执行。失败或结束后，如有需要重新批准连接，再选择源文件与新的保存名称。内容验证和权限检查不代表所有物理跨 NAT 网络可达，也不代表任意磁盘/网络的性能。

## 验证与排障

0.1.23 的统一开关与偏好恢复已通过本地回归和三平台[正式发布工作流](https://github.com/wanghao9103/farsail/actions/runs/39208981511)，包含 Windows 安装/重启及 Linux 原生检查；物理文件对话框与双机验收仍待完成。下方证据保留此前文件传输基线，不代表新增物理设备验收。

本机 TypeScript/Vite、Chromium/WebKit 文件界面及既有桌面界面回归通过。合成 IPC 检查覆盖独立权限、Linux 不共享屏幕时批准文件、对话框取消、接收/拒绝/取消、进度结果、路径文案和窄窗口。

另外，真实隔离 PostgreSQL、协调 HTTP、双 Linux 原生客户端、QUIC 与磁盘文件 actor 的 5 项集成通过；客户端 44 项、传输 17 项、桌面 39 项单元检查通过。真实传输检查覆盖直连优先、UDP 黑洞与缓存中继、仅中继地址发现直连及等待窗口后回退。Ubuntu 原生检查确认接收默认关闭、查看器无法调用文件命令、WebView 无文件读取权限。实际原生选文件/另存为、物理 Windows 与互联网双机验收仍待执行；测试路径及合成 IPC 不能证明这些检查。完整范围与证据见[FILES-031 验证记录](verification/WI-FILES-031.zh-CN.md)。

| 现象               | 检查                                                                               |
| ------------------ | ---------------------------------------------------------------------------------- |
| 文件按钮不可用     | 本机已添加，对方在线且未停用，并已允许远程连接。                                   |
| 没有收到文件       | 独立文件连接需先批准连接并选择保存目标；远控文件粘贴需控制权限，且两端支持该能力。 |
| 保存失败           | 选择新文件名，检查磁盘空间与目录权限，并使用支持硬链接的文件系统。                 |
| 未直连             | 检查已配置的可信中继与面板实际路径；直连受网络条件影响。                           |
| 任务结束或校验失败 | 两端保持登录，远程开关与授权有效，源文件未被修改；重新申请并选择文件。             |

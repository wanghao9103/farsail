# 桌面文件传输

当前源码候选新增 Ubuntu 与 Windows 桌面的双向单文件传输。本页描述该候选实现，不代表旧版已发布安装包具备相同能力。两端客户端与协调服务需一起升级：协调服务必须接受 Linux 文件能力，并保持文件批准与屏幕共享独立。Windows 原生文件对话框与文件系统操作尚未在物理 Windows 机器完成验收；Windows CI 和新的公开安装包仍待完成。

## 发送与接收

1. 两台电脑均登录并首次添加一次本机，保持应用运行。接收方选择本机设备或打开“共享与设置”，开启**允许接收文件**。默认关闭，重启应用后不会自动恢复接收。
2. 发送方在**我的设备**中选择在线接收设备，点击**文件传输**。对方未开启接收、离线或设备被停用时不能接收请求。仅发送文件时，发送方不必开启本机接收。
3. 接收方点击**允许文件传输**。每次文件连接都需要明确批准，包括已开启远程值守的同账号设备。这只授予文件权限，不授予屏幕查看或鼠标键盘控制权限。
4. 连接后进入**文件传输**，点击**选择文件发送**。原生打开对话框选择一个本机普通文件；对方看到文件名与大小，本机路径保留在 Rust 中。取消对话框不会产生传输任务。
5. 接收方看到文件申请后选择**保存到…**或**拒绝**。原生另存为对话框为该文件选择确切目标；取消对话框会保留待处理申请，选择目标前不创建文件。仅批准连接不会自动写入文件。
6. 连接双方均可发送文件。记录显示等待接收、进度、完成、拒绝、取消或失败原因；完成后不会自动打开或执行文件。**取消传输**可停止待对方接收的发送任务或正在进行的任务，**结束文件连接**撤销本次连接。

跨账号时，创建权限为**仅传输文件**的一次性邀请码，把接收设备 ID 和邀请码交给申请方；目标设备仍须批准连接。邀请码不能授予屏幕或控制权限。参见[客户端使用](CLIENT.zh-CN.md)与[授权 API](API.zh-CN.md)。

## 本机范围与完整性

文件使用独立的 `files` 授权与 `Channel::File`；`view`、`control` 会话不能使用该通道。仅当原生传输和本机接收开关有效时，开启接收才声明 `can_files=true`，与 `can_host` 独立。关闭接收先停止本机接收的文件会话，再尝试更新服务器能力；退出登录、停止传输或授权失效也会停止本机操作，迟到的文件对话框结果不能恢复已结束会话。

对方不能浏览本机目录，也不能指定任意本机路径。每次原生打开对话框只授权读取所选的一个源文件，每次原生另存为对话框只为一个已申请的文件指定保存目标。React 仅获得会话/任务编号、显示名称、大小、进度和错误，不获得完整本机路径、签名密钥、账号/设备令牌或授权凭据。

接收方以目录能力句柄打开用户所选的父目录，并在其中独占创建随机 `.farsail-part-*` 文件。检查连续偏移、声明大小和最终 SHA-256 后，以原子且不替换目标的硬链接发布已验证文件。目标已有文件、目录或符号链接时保存失败，包括接收批准后才创建的目标；没有覆盖功能，也不会降级到削弱规则的重命名或复制方式。正常清理时，取消、断开或校验失败会释放接收器并删除临时文件。

请选择支持硬链接的文件系统，例如合适的 ext4 或 NTFS 目标。FAT/exFAT 等不支持硬链接的文件系统无法发布接收文件，会保存失败而非静默改用不安全方法。强制杀进程或断电可能留下 `.farsail-part-*` 文件；确认 FarSail 没有正在传输后，仅检查该任务选定的目标目录，应用不会递归扫描并删除无关文件。

## 连接方式与限制

新文件连接会先对已知 IP 地址提供最多 3 秒的 P2P 直连尝试窗口，再使用已配置中继回退，保留已有 iroh 端点身份与发现状态。高级设置中显式选择的**始终通过中继连接**仍有效；没有可用直连地址时，可以直接使用已配置中继。中继要求正常可信 HTTPS/TLS 校验，不关闭证书检查。面板展示实际选中的直连或中继路径，不保证所有网络都能直连。该策略不会重启或替换已有屏幕连接。

协议每块最多 64 KiB，收到该块确认后再发送下一块。同一应用内所有发出的文件会话共享固定 4 MiB/s 文件带宽预算；这是文件协议预算，不是链路速度、屏幕加文件总流量或网络开销保证。单文件最大 64 GiB。发送方先检查源文件内容，再在发送过程中复核；接收方在报告成功前检查完整 SHA-256。大文件在显示申请前需要时间计算摘要。

当前限制：仅单个普通文件；不支持递归目录、远端目录浏览、覆盖、断线暂停/续传、选择性压缩或自动执行。失败或结束后，如有需要重新批准连接，再选择源文件与新的保存名称。内容验证和权限检查不代表所有物理跨 NAT 网络可达，也不代表任意磁盘/网络的性能。

## 验证与排障

本机 TypeScript/Vite、Chromium/WebKit 文件界面及既有桌面界面回归通过。合成 IPC 检查覆盖独立权限、Linux 不共享屏幕时批准文件、对话框取消、接收/拒绝/取消、进度结果、路径文案和窄窗口。

另外，真实隔离 PostgreSQL、协调 HTTP、双 Linux 原生客户端、QUIC 与磁盘文件 actor 的 5 项集成通过；客户端 44 项、传输 15 项、桌面 39 项单元检查通过。真实传输检查分别验证了直连优先、UDP 黑洞后的可信中继回退及缓存中继仍保留直连窗口。Ubuntu 原生检查确认接收默认关闭、查看器无法调用文件命令、WebView 无文件读取权限。实际原生选文件/另存为、物理 Windows 与互联网双机验收仍待执行；测试路径及合成 IPC 不能证明这些检查。完整范围与证据见[FILES-031 验证记录](verification/WI-FILES-031.zh-CN.md)。

| 现象 | 检查 |
| --- | --- |
| 文件按钮不可用 | 本机已添加，对方在线且未停用，并已开启允许接收文件。 |
| 没有收到文件 | 先批准文件连接，再为每个文件申请选择保存目标；仅批准屏幕连接无效。 |
| 保存失败 | 选择新文件名，检查磁盘空间与目录权限，并使用支持硬链接的文件系统。 |
| 未直连 | 检查已配置的可信中继与面板实际路径；直连受网络条件影响。 |
| 任务结束或校验失败 | 两端保持登录，接收开关与授权有效，源文件未被修改；重新申请并选择文件。 |

# 休眠在线唤醒

2026-11-12。接续 WI-051：仅续期共享锁，未能阻止这版 ColorOS 在断电熄屏约五分钟后撤销两个 CPU 锁。实际拔掉 USB 的采样出现 125 秒心跳中断，超过 60 秒设备在线租约。

增加一个提前 25 秒的显式、不可变、非导出 `ELAPSED_REALTIME_WAKEUP` 任务。仅当已认证的在线前台服务运行、保持在线已开启、保存的身份范围仍匹配、手机熄屏且未充电、用户已授予电池豁免时启用。Android 12 及以上另检查 `canScheduleExactAlarms`，捕获权限拒绝。未增加新权限、Shell 白名单、隐藏标志、伪装闹钟界面、虚假音频或传感器活动。已检查的这台手机 `AlarmManagerService$3.set` 会自动为用户电源白名单 UID 使用不受普通休眠间隔限制的派发路径。这是针对该固件的测试依据，不保证所有安卓设备都按该频率派发。

普通 15 秒调度保留已安排的截止时间，不不断向后推迟。实际系统唤醒任务消耗该截止时间，经过现有独立工作线程发送新心跳，再安排下一次。工作线程仍检查原生身份范围和授权。广播异步 CPU 派发在请求结束或独立的八秒超时后结束，不亮屏、不解锁、不恢复录屏授权、不自动批准远程控制。没有存活服务时，任务取消自身，不重新建立共享。充电、屏幕亮起、关闭功能、身份切换和服务停止时取消相应任务；迟到派发不能复活已关闭调度。

本机通过 20 项 JVM 测试、debug lint（零错误、52 条警告，含预期的精确定时任务用户豁免提示）和仪器测试 Kotlin 编译。四项新增测试覆盖普通调度导致截止时间不断推迟、取消、关闭后迟到派发和调度权限拒绝。使用原证书及未变化的已验证原生库构建 `0.1.17-idle1`。真机验收待完成：先观察五分钟撤锁点后的真实系统任务派发，再经过足够长的实际拔线验证心跳不中断及已授权远程访问。不能因单元测试或 USB 连接模拟通过就宣称离线已解决。

真机结果：不能作为主要心跳时钟。原签名候选包已覆盖安装到被测手机。系统任务记录显示，请求的 25 秒唤醒被推迟至约五分钟后，非精确窗口约 18.7 秒，标志为 `0x8`，用户电池豁免仍有效。连续七分钟熄屏模拟完成，但只派发两次系统任务，两个应用 CPU 锁也再次消失。USB 保留了观察通道，因此模拟中普通心跳正常不能证明实际拔线可用。供电报告和休眠控制均已恢复。此调度仅保留为有限的恢复后备；WI-053 改用真实协调端响应 I/O，解除主要心跳对本地定时器的依赖。

# Concurrent viewers, session tabs and retained window geometry

Date: 2026-11-05. Baseline: main `e5bddf0`. Initial validation used desktop 0.1.35 / Android 0.1.10 before publication; release results are below.

## Changes

- New outgoing viewers join one native window as tabs. Each retains its own native session binding, cancellation, recovery instance, display selection and input generation. The application menu can open subsequent connections in separate windows.
- Click a tab, use arrow keys on the tab strip, Ctrl+Tab / Ctrl+Shift+Tab, Ctrl+PageUp / PageDown or Ctrl+1…9 to switch. Ctrl+W / the tab close button ends only that connection. The native window close button ends all its tabs.
- Inactive tabs stay connected and retain their latest picture, but pause frontend frame polling/decoding. Native transport continues media acknowledgement. Switching away invalidates queued input and releases held input in order; selecting another phone cannot receive the previous phone's keys.
- Automatic phone sizing is owned by the native window lifetime. Fresh session IDs after recovery, tab changes and remote orientation changes cannot overwrite the window's chosen geometry. Local phone display rotation survives recovery.
- Status polling permits one outstanding request per viewer, preventing overlapping work under load. The baseline already contains independent transport lease validation, fresh generation-bound proof caching, decoded-image presentation and removal of the coordinator's remote request quota; these fixes were retained and exercised rather than replaced with relaxed authorization.
- Android keeps its existing immersive canvas, floating controls and remote orientation following. The first frame hides tools after 700 ms. Added enlarge/reduce actions and an explicit fill-screen option; cropping, pinch/pan and touch inversion share the same geometry. Empty viewer intents do not start a connection.

## After 0.1.38: overflow tabs and adjacent close (unreleased)

The device strip compresses short labels in a wide window and provides left/right paging plus horizontal wheel browsing when it overflows. Browsing neither selects a device nor expands remote controls. Selecting a device reveals its tab and retains keyboard focus after the old panel's strip unmounts. Narrow windows keep readable active labels, all window controls and a native drag area of at least 44 pixels. Closing the current tab selects its right neighbor, or the left neighbor at the end; closing a background tab preserves the current selection. Native host authorization and synchronous cancellation before asynchronous cleanup remain unchanged.

The previous WebKit timeout was also diagnosed: after the file-transfer toolbar rerendered, moving off it emitted new pointer-over/move events without the old exit events. DOM hover was false but the saved hover flag remained true, preventing automatic hiding. Replacing mouse-leave with pointer-leave alone still failed. A capture-phase pointer-move handler now only clears stale hover bookkeeping and schedules hiding; it never reveals controls or changes remote input. The unchanged baseline failure and both minimal experiments remain in `.local/webkit-toolbar-20261105/`.

Evidence: `.local/viewer-overflow-20261105/verification.json`. The production build, 17 viewer policy tests, desktop Rust library (58 passed, 1 existing ignored), all-target Clippy, Rust formatting and complete Chromium/WebKit viewer suites passed. New checks cover 5 short tabs at 1200 pixels without overflow, local wheel/paging, selected-tab visibility and focus, adjacent/background close, and controls plus drag bounds at widths 440 and 320. ## 0.1.39: ordered rapid selection

The workspace now shares an ordered mutation queue for selection and close, plus a single-flight native-tab reader. A user intent advances its revision before optimistic selection; snapshots from older revisions or lifetimes cannot replace that choice. Once mutations settle, a fresh native snapshot restores truth, including a failed latest selection, newly opened devices and recovered session IDs. Effect replay retains the same controller so its old read cannot overlap a new one. Superseded selection failures are discarded, while close failures remain visible even after a newer selection succeeds.

The release source is `74a5e41a39754f984eaaf7f8e6a7066e013c314a`; packaging is tracked separately below. Production build, 30 pure state tests (including 9 new tab-policy cases), and complete Chromium/WebKit viewer suites passed on this source. Browser faults hold an old A snapshot and a B operation while the user chooses C/E, verify last-intent preservation and maximum 1 read/mutation in flight, then exercise failed selection, ordered close and a close failure followed by successful selection. Existing input isolation, fullscreen and overflow regressions remain included. Evidence: `.local/viewer-races-20261105/verification.json` and its final browser logs. These are synthetic IPC checks, not physical multi-phone measurements.

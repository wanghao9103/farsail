# WI-008A Public-IP Deployment Package Verification

Starting HEAD `58db323bdc523132377903e83b853a08c6a981a5`, with a clean working tree. See [IMPLEMENTATION](../IMPLEMENTATION.md) for the exclusive serial Write Set. <a id="实现及构建"></a>

## Implementation and Builds

- Built the coordinator with Rust 1.93.0 and Cargo.lock; built upstream iroh-relay 1.2.0 through `cargo install --locked` using its release lockfile. Both Linux amd64 images were actually built successfully in local Docker. Runtime uses Debian slim + CA, user 10001, and migrations embedded in the coordinator binary. Pinned dependency-runtime image digests are in deploy/production/images.json.
- Linux Compose shares the gateway network namespace. The coordinator remains on 127.0.0.1:8787, the database is private-network only, SMTP is loopback 1025, and Mailpit is host-loopback only. Public 443/API and 8443/relay are separate, and the EIP is not treated as a local bind IP. Every service uses pull_policy=never.
- Internal admission POST checks the private bearer, registered public key, bound/enabled device, verified/enabled account, and a login that is not revoked and whose refresh has not expired, with a 2-second database deadline. Upstream lacks an overall HTTP timeout; a loopback Nginx frontend uses a 1-second connection timeout and 3-second read/write timeouts. Public access to /internal is blocked. Per-client RX is 2 MB/s with a 4 MB burst. Unimplemented accept_conn_limit/burst settings are not used.
- Bash deployment/packaging scripts use fixed-SHA application tags and fixed dependency tags. After loading, they verify six config SHAs/platforms and attachment SHA256. Full archive validation covers all config/layer members rather than letting existing local images mask missing layers. The GitHub workflow publishes prerelease attachments only after real Compose/identity/relay tests pass.

## Measured Findings

A real wire test corrected an upstream naming discrepancy: the actual literal value of iroh-relay 1.2.0 constant `X_IROH_ENDPOINT_ID` is `X-Iroh-NodeId`. The inferred Endpoint-Id produced 400 and caused client online timeouts. Admission code, dedicated tests, and documentation now use the actual source header. Manual curl unit checks cannot replace real binary connections.

The external Rust relay probe compiled. Local Docker ran the real database, coordinator, Mailpit, Nginx, and relay. Upstream’s plaintext root path returned 404, so health checks were corrected to the actual generate_204 endpoint; TLS uses healthz. Windows Schannel encountered a temporary CA with no public revocation information. Tests used only ssl-revoke-best-effort to tolerate a missing CRL while still validating the CA chain/IP SAN and requiring default system trust to reject the temporary CA. Linux/production use standard TLS, without -k or accept-all.

Backend, transport, and Windows client CI all succeeded for implementation commit `9d910e6b36a2f4faed5da7f2be58fb0773ef3714`. The first deployment CI passed all Compose/HTTPS/relay/rotation/failure checks, then the host Rust database test hit PoolTimedOut. Inspection showed pg_isready worked inside the database container on its internal-only network, but no host port was published. `4252e9d901e3022175772f563be45df967c3e9cc` added only this project’s egress network to the test.override database while retaining host binding 127.0.0.1:55433; the production database exposes no port. Local postgres_flow and Clippy passed afterward. The same commit handled Windows jq CRLF and sha256sum’s asterisk format; application runtime logic was unchanged.

The local archive contains six images. After checking each config and every referenced layer, only the six fixed tags generated by this item were deleted. docker load then successfully checked IDs/platforms and SHA256 one by one. User image caches were not cleared. “Full layer inventory + delete this item’s tags and reimport” provides equivalent integrity evidence, while actual public artifacts still require checking. Compose tests used no -k: normal CA/IP verification for API/relay, real Mailpit email verification/registration/signed binding, explicit bootstrap admin, real forced-relay bidirectional payload and selected path, unknown/disabled identities, and rejection after coordinator/relay outages all passed. After a full force-recreate, existing accounts/devices still connected. Test certificate rotation made API/relay return the new serial; an incorrect certificate caused nginx -t to fail.

A Docker stats snapshot after idle fault recovery showed coordinator 1.715 MiB, database 20.07 MiB, gateway 10.69 MiB, Mailpit 6.113 MiB, and relay 5.133 MiB, about 44 MiB total. ## Fixed Public Artifacts

**Use fixed loader 51e131f with the original 4252e9d runtime archive.** Classic `.Id` is a config digest, while containerd `.Id` may be a manifest/index digest; the original loader in 4252 wrongly rejects valid images. The fix verifies config SHA and reads it again from streamed docker save after import. Configs contain rootfs diffIDs, strictly verifying complete runtime content. New packaging manifests record `config_digest`. The old 4252 manifest came from classic storage, so its original id-as-config-SHA semantics are supported precisely while pinning the audited manifest/archive SHAs. Existing state and complete download caches can remain; the nearly 300 MB archive need not be downloaded again.

## Delivery Boundaries and Follow-up Interfaces

- See `docs/API.md` for API requests/responses, credential usage, and configuration. WI-002 can integrate `/v1/me`, `/v1/auth/*`, device challenge/binding/list APIs, `/v1/remote/{id}` status, and administrator APIs. Device private keys must use client platform secure storage and never enter WebView localStorage.
- Grant tokens from `POST /v1/remote/{id}/decide` and `/renew` are returned only to the controlled device, never in initiating-device status queries. WI-003 must add authenticated signaling exchange, iroh handshake identity/permission checks, revocation on real disconnection, and shared P2P/relay validation. The current database authorization state machine alone cannot prove revocation on image/input/file paths.
- There is currently no public address, domain, real SMTP, cross-network path with a second device, or mobile physical-device validation. Production TLS proxying, external rate limiting, persistent audit monitoring, and backups are not configured. The service rejects non-loopback listening and has no option to disable TLS certificate verification.

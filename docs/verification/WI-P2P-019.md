## Behavior

- New outbound and inbound handshakes request fresh discovery on the existing endpoint. Native outbound refresh happens before fetching the peer address.
- Re-inserting the exact configured relay with `Endpoint::insert_relay` queues Iroh 1.2.0's `RelayMapChange`, classified as a major/full report. No relay removal, endpoint replacement, copied diagnostic socket address, identity rotation or transport/grant teardown occurs. Version-specific cached source was inspected; the executable QAD regression validates the behavior.
- A shared endpoint lock and 30-second cooldown coalesce all sessions and callers. Actor enqueue is bounded to one second. Relay-only live sessions trigger a retry on the native 30-second maintenance tick. Good direct sessions do not trigger maintenance refresh, and status polling never requests it. A recent handshake can defer the next maintenance request to the following tick; discovery success is not required to continue media over relay.
- `watch_addr` publishes changed addresses after 250ms coalescing, without waiting for the ordinary heartbeat. Failed uploads retry on maintenance/heartbeat. Old/new endpoint uploads are serialized and checked against lifecycle and heartbeat generation; queued stale snapshots are rejected. In-flight HTTP uploads finish under the publication lock because dropping a client future does not cancel an already-running server write. HTTP retains its existing 15-second bound; stale generations also remain rejected by the coordinator.
- Public viewer/main status separates selected direct/relay paths from scheduling state: trying direct, relay fallback with periodic retry, refresh scheduling failed, or explicitly forced relay. It does not expose addresses, identity, grants, network reports or inferred NAT classifications. Scheduling success is not represented as QAD success.
- Forced relay and no configured relay skip QAD refresh. Existing 16-session/8-handshake caps, lease deadline, replay, revocation, control permission and input cancellation remain in force. Unused approvals remain valid.

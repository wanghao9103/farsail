## Local Verification

- `cargo test -p farsail-coordinator` passed against real PostgreSQL in isolated `fs_test_<uuid>` schemas. Added tests for address publication/discovery, registered-key matching, rejection of old heartbeat generations, delayed old UPSERTs not overwriting new generations, constrained relay URLs, current grant generations, and remaining server TTL. Isolated schemas were deleted after tests.
- `cargo test -p farsail-transport` passed with real local iroh endpoints: bidirectional media frames, view permission denying control frames, wrong public keys not consuming grants, rejection of unapproved/expired fields/permission escalation/replays, more than two consecutive rotations, closure after service revocation, independent `Instant` deadline closure while the authorization service blocks, and a silent handshake not blocking another connection. The forced-relay test ran a self-hosted iroh-relay on loopback HTTPS with a temporary certificate and explicit test CA. After both endpoints called `clear_ip_transports()`, neither had IP addresses, the selected path was `relay`, and media frames were actually sent/received. No accept-all TLS verifier was used.
- `cargo test -p farsail-client` passed with real PostgreSQL, Axum HTTP, and native iroh at both ends: registration/email verification/signed device binding/heartbeat; first startup after approval not consuming an unused grant; target address discovery; encrypted grant delivery; bidirectional frames; permission rejection; old requests unusable after the target disconnects/restarts with the same identity; successful connection after a new request and approval; and existing sessions closing after revocation. Tests temporarily mark the target `can_host=true` only in isolated schemas; the production desktop client still registers false. Additional tests covered delayed address publication racing with stop, old connection completion unable to write into a new lifecycle, and local logout completing first under slow HTTP.
- Existing development database data was retained during a measured migration. Before startup: `users=1`, `_sqlx_migrations=1`. After the real coordinator ran: `/healthz` was 200, `users=1`, `_sqlx_migrations=2`, and the new `device_endpoint_addresses` table existed. Historical volumes were neither rebuilt nor cleared.
- `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-transport.ps1`: passed, including `cargo fmt --all -- --check`, 1 coordinator PostgreSQL integration test, 7 transport tests, 7 client unit tests and 1 real HTTP/iroh integration test, `cargo clippy -p farsail-core -p farsail-transport -p farsail-client -p farsail-coordinator -p farsail-desktop --all-targets -- -D warnings`, `npm run typecheck`, `npm run build`, and Windows `cargo build -p farsail-desktop`. The frontend build verifies types/packaging; the Tauri build verifies native-command compilation. Browser previews were not treated as real cross-device remote-control evidence.

The system firewall was unchanged, no real email was sent, and no public server was deployed.

After acceptance, `scripts/test-coordinator.ps1 -Stop` stopped only the two `farsail-dev` containers. Ports 8787, 1420, 55432, 51025, and 58025 had no listeners; dynamic Axum/iroh/relay ports closed with their processes. Ignored `.local/dev.env` and this project’s Docker volumes remain. Other Docker services were untouched.

The current `Session` carries only bounded typed frames. Capture/input handling, file content/resumption, cross-NAT operation, public IP certificates and a second real device, physical mobile devices, sustained performance, and outage scenarios still need later verification. The relay test uses a test authorization implementation; complete real database/HTTP integration was verified over local direct transport. These cannot be combined into a claim of verified public-relay authorization.

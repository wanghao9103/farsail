# 远程可靠性 / Windows 0.1.2

基线：`024eb05d89c65318b707605774897f0706574ff2`；规划提交 `01817f0`。工作与已暂停的文件传输进行中工作隔离。不修改协调服务器路由、迁移、已部署密钥或生产配置。协调服务器远程/设备实现与已发布的 `deploy-4252e9d901e3022175772f563be45df967c3e9cc` 载荷保持一致；此客户端不要求服务器升级。

<a id="findings-and-implementation"></a>

## 发现与实现

- 报告称连接约 30 秒后结束；它不能证明此前输入可用。真实 PostgreSQL/HTTP/QUIC 测试维持连接 70 秒，跨越多个按生产节奏执行的授权轮换、心跳及双向数据传输。本地未复现固定时长失败；生产根因仍未证实。
- 旧同步输入门禁对租约期限使用 `try_read`。进行中的续期可能因此看似会话过期。期限现在使用短同步读/写临界区；持锁期间没有 I/O 或 await。竞争回归在持有写锁时检查活动输入门禁。实际有限授权 TTL 和权威检查不变。
- 应用现在容忍有界输入乱序，不依赖隐含跨流保证。主机现在最多缓存 32 个小输入命令，最多 2 秒，连续命令仅应用一次，并在缺失、重复或过量序列时安全关闭。实际 iroh 测试先交付不完整的较早流；它验证超时/丢弃后收到完整较晚帧，以及关闭原因传播。它不能证明乱序是所报告失败的原因。UI 在鼠标按下时明确聚焦桌面，归一化通用修饰键，在失焦/失败/关闭时取消排队工作，并在原生发送前立即再次检查输入门禁。旧显示坐标被丢弃；实际输入注入失败以有界公开原因关闭。
- 终止状态清除 JPEG URL、FPS 和排队输入。公开原因码区分停止、授权检查、续期、过期、媒体超时、采集和输入失败，不输出 token 或原始传输日志。
- 媒体仍有每流 400 ms 期限及 1.5 MB/s 载荷预算。孤立的丢帧/ACK 可重试；静态桌面重试最后可用帧，而不是无限等待新像素。重复图像会确认但不重新显示。每次尝试等待 ACK 最多 2 秒，最多连续失败 3 次（最多 3 个未确认的有界帧），之后关闭。有新帧时替代过期帧；这是有界 JPEG 基线，不是自适应视频。
- 查看器是独立原生窗口。显示器选择、路径/RTT 和控件紧凑显示；详情折叠。窗口操作仅作用于调用的查看器。关闭它会取消恢复并撤销当前/待处理会话，同时保留主设备管理器。主窗口退出登录/关闭/撤销会取消受影响恢复。查看器命令在 Rust 中强制校验绑定会话 ID；账号/管理员/设置/托管命令要求 `main`。查看器 webview 不获得通用跨窗口权限或窗口创建命令。
- 网络/媒体超时可在每个查看器生命周期中发起总计最多 3 次自动尝试，每次都使用全新请求 ID 及协调服务器新批准/授权。拒绝、已撤销/过期权限、明确停止、身份变化和不可用/已禁用目标不会恢复旧授权。取消立即使绑定失效，并补偿迟到请求/连接结果。旧客户端含糊的通用关闭为终止状态。现有已认证 iroh 连接内路径迁移与重连不同；UI 根据实际所选路径显示 `P2P 直连`、`中继回退` 或协商中。强制中继仍需主动选择。
- `远程值守` 是本地内存设置，在当前共享时段默认关闭，需主动启用。文本：“开启后，同账号设备可直接连接，无需逐次批准”。原生主机将权威待处理请求者 ID 与绑定账号比较；仅查看/控制可自动批准。现有协调服务器身份/设备/授权检查仍是权威依据。其他账号继续待批准。停用会结束入站会话、移除/撤销未完成本地批准，并恢复手动决定。纪元检查补偿停用/停止/退出登录后到达的批准响应。停止共享、退出登录和进程重启禁用此设置。它要求已登录的交互式 Windows 桌面和运行中的应用；不支持 UAC 或登录屏幕。

<a id="verification-record"></a>

## 验证记录

- 真实协调服务器集成：隔离 Docker 项目 `farsail-reliability`，PostgreSQL 17，动态分配回环端口，随机生成且被忽略的凭据，临时 DPAPI 配置，模拟身份，模式清理。`cargo test -p farsail-client --test coordinator_flow` 通过，包括 70 秒生产节奏续期、旧授权重放拒绝、其他账号不自动批准，以及同账号默认关闭/主动启用/已撤销状态行为。
- Client 单元回归包括停用后延迟自动决定的补偿；本地不留授权并发送撤销。现有主机/传输启动取消及离线退出登录检查保留。
- 浏览器测试 `scripts/test-desktop-ui.cjs` 和 `scripts/test-remote-viewer.cjs` 通过：注册/登录、共享、请求/取消、原生窗口派发、焦点/按钮/按键提交、终止图像清理、排队输入取消、授权终止关闭不重试、网络关闭仅调用一次恢复、取消及仅查看输入抑制。截图仅使用模拟图形。这是模拟 IPC 证据，不是实体双机控制。
- `cargo test -p farsail-windows real_input_into_own_foreground_window -- --ignored --test-threads=1` 在此 Windows 主机通过：向测试拥有且已验证前台/PID 的窗口注入无害文本、修饰键/选择和点击。未针对私人窗口，也未保存桌面图像。
- `scripts/test-native-viewer.ps1` 在真实 Windows WebView2 进程中使用自身 DPAPI 和 WebView 配置通过：8 项禁止的账号/管理员/设置/托管/其他会话/跨窗口命令被拒绝；原生最大化、全屏、最小化和查看器销毁已验证。查看器关闭后主窗口仍存在，进程保持存活。此夹具不声称验证实时远程媒体会话。
- 前端类型检查/生产构建、Rust 格式检查、针对性单元回归和 Clippy `-D warnings` 通过。产物验证后追加精确的最终 CI/发布证据。

<a id="limits-and-compatibility"></a>

## 限制与兼容性

两端都应升级，以获得乱序输入容忍、更丰富的原因和媒体重试行为。线路协议/ALPN 不变，旧协调服务器仍兼容；不需要服务器重新部署或新镜像归档。静态桌面在会话活跃时可正确显示 0 FPS。屏幕采集仍为约 5 FPS JPEG。不声称跨 NAT 成功率、实体双机交互、提权窗口控制、无人值守登录、HEVC、文件或移动端支持。安装程序仍为未签名预览版。

参考：[Tauri 能力默认值](https://tauri.app/security/capabilities/)、[iroh Connection API](https://docs.rs/iroh/1.2.0/iroh/endpoint/struct.Connection.html)。自定义应用命令默认可调用，因此每个相关 Rust 命令内部都检查窗口标签和当前会话绑定；单靠能力名称不是安全边界。

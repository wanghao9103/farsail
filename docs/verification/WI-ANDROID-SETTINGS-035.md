# Android sharing settings — 0.1.9

Home now shows My devices directly, with device discovery and Control / View only actions. Local hosting is under Settings → Share this phone; its subpage owns screen sharing, same-account control, screen-timeout protection, foreground restoration and accessibility setup. Incoming requests expose a home entry and are approved or rejected on the sharing subpage. Returning from accessibility setup or restoring sharing enters that subpage while preserving the settings return path.

MainActivity and DeviceListActivity reuse DeviceListContent. Leaving a page invalidates its asynchronous discovery callbacks. MobileUi applies system-bar, display-cutout and keyboard insets to the clipped scroll viewport so padding does not scroll under the status bar. The minimum API remains 26; navigation-bar theme attributes live in versioned API 27 resources. No new remote permission or recording-token persistence is introduced.

Owned API 35 emulator validation passed for home/settings separation, settings navigation, incoming-request actions, form isolation, accessibility setup and visible sharing failures. The initial System UI ANR was captured separately. A host regression still expected Stop on Home after task removal; after following the new settings route, real MediaProjection, background/task-removal survival, Stop and notification/wake-lock cleanup passed. The earlier failing run is retained.

Actual process replacement passed for remembered control, fresh recording consent, cancellation, explicit Stop and stale/different-device denial. Real JNI/QUIC controller regression passed for synthetic desktop/phone peers, a static frame beyond six seconds, touch/drag/wheel/text, view-only rejection, rotated input, background closure and pending cancellation. Kotlin unit tests and lint passed. Local evidence is under `.local/android-navigation-verification/`, `.local/android-memory-verification/attempt-1793693916725949497/` and `.local/android-controller-verification/attempt-1793693993046810019/`.

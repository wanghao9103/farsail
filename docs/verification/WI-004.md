## Implementation and Local Evidence

- `crates/windows` creates D3D11 duplication on the DXGI adapter owning the enumerated target monitor, maps BGRA with row pitch, handles geometry/negative coordinates using DXGI rotation and per-monitor DPI, and scales to JPEG-baseline dimensions in memory. `cargo test -p farsail-windows real_dxgi_frame_stays_in_memory -- --ignored --nocapture` established duplication on the local active monitor and completed JPEG encoding, protocol validation, and RGB decoding from a real frame, without saving a screenshot. Monitor changes/`ACCESS_LOST` close the session with a retained reason; reconnection requires approval again.
- `crates/client/tests/coordinator_flow.rs` used isolated schemas in real PostgreSQL, Axum HTTP, and two real iroh endpoints for registration, device proof, heartbeats, enabling host capability through the normal API, cross-account invitations, explicit target approval, authenticated connections, and media transmission/reception. With `FARSAIL_REAL_CAPTURE=1`, the target captures a real DXGI frame, sends JPEG through the session, and the peer decodes/verifies dimensions. The same test also sends synthetic JPEG and checks a negative origin. It does not directly modify `can_host` in the device table.
- `cargo test -p farsail-windows real_input_into_own_foreground_window -- --ignored --nocapture` creates its own temporary EDIT window and first verifies its foreground HWND/process ID. Failed verification attempts stop before injection. A successful run sends only “FS,” Shift+Home, replacement character “Q,” and a left click inside that window, then releases input and destroys the window. Separate synthetic tests cover right Ctrl/Alt/navigation extended flags, all four rotations and row pitch for non-square images, negative coordinates, stale-layout clicks, tiny wheel values, and extra input fields. No input was injected into terminals or other user applications.
- `scripts/test-remote.ps1 -SkipServices -RealCapture` includes formatting checks, media/Windows/transport/client/desktop Rust tests, full Clippy, frontend typecheck/build, and a Windows Tauri native build. Project services were started by `scripts/test-coordinator.ps1` and passed real PostgreSQL regression; existing volumes were retained after testing. Transport tests cover view permission rejecting Control, incorrect identity, lease revocation, forced local TLS relay, replay, and continuing to receive complete frames after a media-stream reset. `ByteBudget` and `wait_for_ack` tests verify sustained payload ceilings and slow-consumer acknowledgment deadlines respectively. The production host retains only the newest frame, waits for a viewer ACK for each frame, and runs media sending independently from control reception.
- The final complete command exited 0: 3 media tests, 6 synthetic Windows tests (2 native smoke tests explicitly ignored according to environment), 8 transport tests, 8 client unit tests plus 1 real-service integration test, and 1 desktop single-instance test all passed. `cargo clippy ... --all-targets -- -D warnings`, `npm run typecheck`, `npm run build`, `cargo build -p farsail-desktop`, and `cargo fmt --all -- --check` passed. The controlled-window native input test ran separately and passed.
- A real WebView2/debug Tauri IPC smoke test in an independent temporary configuration directory and local Vite (`127.0.0.1:1420`) returned `{ok:true,mediaMagic:"FSM1",mediaBytes:679}`, proving frontend receipt of a native raw binary response. ## Security and Actual Boundaries

The local page shows only view/control state, actual received FPS, path RTT, monitor selection, explicit stop, and a TLS exporter verification code; long-term credentials and grants stay out of WebView. JPEG payload has a sustained 1.5 MB/s budget, a 700 ms frame-age ceiling, and a 1-second consumer ACK deadline. This excludes QUIC/TLS/IP overhead and retransmissions; no public-network performance measurements exist. Actual pictures pass only through memory and never enter Git, CI artifacts, logs, or public reports.

Windows secure desktop/UAC, no signed-in user, a second real Windows machine, public IP certificates/cross-NAT operation, and physical mobile devices are outside local verification. Real dual endpoints and a real database establish normal two-party authorization and native capture/decoding. WebView IPC uses synthetic JPEG to verify the binary interface, without claiming human remote-control operation on a second machine. GitHub Actions has no interactive desktop and runs only synthetic media, protocol, permission, and compilation tests. Real capture and foreground-window injection ran locally only.

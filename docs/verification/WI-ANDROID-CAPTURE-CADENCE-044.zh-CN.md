# 安卓采集节奏与 JPEG 加速

2026-11-06。排查确认普通录屏入口明确限制为每 100 毫秒一帧，原 JPEG 编码库的 SIMD 仅支持 AVX2。在一台已连接的 ARM 手机上，48 秒观察得到约 8.37 帧/秒；缩放加编码耗时中位数 48 毫秒、p95 为 77 毫秒。这只是单台设备和当前负载的观察，不是受控的编码器基准，也不能解释所有停帧会话。

候选实现仅在安卓静态集成 libjpeg-turbo，质量 80–90 继续保留 4:4:4 采样、原有几何检查、字节上限和协议。每个线程复用压缩器，其他平台保留原编码器。普通录屏采集目标为 30 FPS，容忍小幅显示时钟抖动，更换采集表面时重置，慢编码后不会突发追赶旧帧。仍只获取最新缓冲，原有需求门禁及有界发送机制继续生效。原本地诊断增加采集节奏、转换和 JPEG 编码分段耗时。

本地验证：安卓 Rust 25 项、媒体 10 项通过，all-target Clippy、格式和 shell 语法检查通过。JVM 12 项通过，含三个新增采集节奏用例。Windows 中文路径下所有测试类均出现加载失败，同一源码复制到 ASCII 临时目录后通过。这些宿主测试没有执行安卓专用原生编码器；CI 额外生成 ARM 媒体测试程序，以便先在连接的手机上验证颜色、几何、大小边界和短时合成编码对照，再安装 APK。

`4f12158` 的原签名候选构建成功。连接的 ARM 手机上，10 项原生媒体测试全部通过，覆盖全色彩采样、几何和字节边界。显式合成对照使用 1088×502、质量 80，各编码五张相同输入：原编码器合计 177,291 微秒，加速编码器合计 67,527 微秒；输出分别为 568,032 与 568,248 字节。这只测量 shell 测试进程中的合成 JPEG 编码，不是游戏采集、缩放、传输、显示帧率或应用整体加速比。候选保持现装签名，校验后仅对一台手机进行了试验更新。文档语言切换检查已在本地修复，71 对文档通过。

待验收：更新后的真机采集测量及五个窗口。尚不能宣称实际显示达到 30 FPS，或重连问题完全解决。候选不修改辅助功能截图间隔、服务端和公开更新通道。

后续补证：手机界面单独显示本机短编号，与其他设备列表分开。本地诊断仅增加绑定编号、采集/共享标志及会话编号，不含访问令牌或密码。`sent` 兼容保留为最新帧序号，新增 `sentFrames` 才是媒体发送完成次数。存在被覆盖或未发送帧时，不能把序号差值当作发送帧率；原约 8.37 FPS 基线为发布帧率，其中 `sent` 差值不代表发送次数。性能验收前必须以实际设备编号核对 USB 试验手机和桌面连接目标。

2026-11-07 补测：观察到五个独立桌面会话均走直连。另一台连接手机使用原编码器，52 秒采样约产出 8.37 FPS，编码中位数 56 毫秒，RTT 中位数 95 毫秒，应用 ACK 中位数 343 毫秒。这些数字不是实际显示帧率。第一台试验手机在用户报告共享故障后已保留数据回退，但回退未恢复共享，原因仍未确认。实物 USB 对应关系已确认，之前推断的设备名称仍未得到验证。后续界面在首页和共享页按实际设备 ID 读取注册名称；独立的名称显示分支保留原生实现。

试验发送器仅在 ACK、写入耗时和 RTT 显示链路健康时允许现有两个有界槽位重叠发送，排队后立即退回单帧等待；15 秒无进展截止及有界停帧探测继续生效。诊断增加 `overlapAllowed`。五会话合成对照使用 1088×502 预编码图像、30 FPS 源和受控的接收端 ACK 延迟 50 毫秒：原单帧等待每路 11.97–12.10 FPS，总有效载荷 142.71 Mbit/s，各路 p95 帧龄最大值 68 毫秒；自适应重叠为 15.60–15.73 FPS、178.19 Mbit/s 和 89 毫秒，两次均无会话关闭。质量反馈范围分别为 80–90 与 80，因此不是固定质量的编码基准。提高吞吐同时增加带宽和帧龄；测试不含采集、编码、WebView 解码/绘制及真实无线争用，不能证明五台手机已有改善。隔离 CI 还测试五路 1088 像素画面共用 35 Mbit/s、持续 120 秒，要求会话保持开启、原生接收 p95 帧龄不超过 1500 毫秒；该上限是拥塞检查，不是流畅游戏目标。候选标记为 `0.1.14-perf3`，尚未正式发布。

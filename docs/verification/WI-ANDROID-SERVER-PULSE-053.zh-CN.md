# 服务端驱动的安卓休眠心跳

2026-11-12。WI-051 记录 ColorOS 撤销 CPU 锁后心跳中断 125 秒；WI-052 确认本地唤醒任务也被合并到约五分钟。两者均超过未改动的 60 秒设备在线租约。准备协调端和安卓配套更新，由真实网络响应触发下一次已认证心跳，不再等待手机休眠期间暂停的主线程定时器。

## 协议与授权

`POST /v1/devices/heartbeat` 增加可选 `wait_for_next: true`，必须携带已建立的 `generation`。现有请求仍立即返回，响应格式不变。选择等待的请求仍需原设备凭据、已绑定且启用的设备、启用的账号和未撤销的登录会话。服务器只在收到实际请求时续约，释放数据库连接，等待 15 秒，再检查凭据、设备代次和剩余租约，返回 `standby_wait_ms: 15000`。发送响应不续约设备；返回的 `expires_in` 扣除服务端等待时间。最多同时等待 512 个延迟请求，等待时不占用数据库连接。无需迁移数据库，不修改远程授权。

原生独立在线通道保留身份缓存修订、范围检查、退出取消及响应后身份验证。仅该请求使用 35 秒 HTTP 超时，其余调用仍为 15 秒。响应大小和 HTTP 错误分类限制保留。JNI 操作绕过账号和 UI 状态锁，不改动传输帧派发、录屏权限或远程批准。

## 安卓工作线程

已启用的在线前台服务在收到延迟响应后，直接从专用工作线程发下一次请求。心跳检查点和间隔统计也在该线程更新，UI 刷新和端点维护不能阻塞它。每次请求前检查保存的身份范围、服务代次和保持在线开关。拒绝及身份替换终止当前任务；服务停止后不再发送新请求，已发出的网络请求仍受超时约束。

旧服务器忽略可选请求字段，响应没有延迟标记。客户端回退到普通定时心跳，并提示需要升级服务器。声称已等待但实际立即返回的响应，也不能造成请求忙循环。重新打开 App 会重试能力检测。限时系统唤醒调度只作为恢复后备。不使用虚假媒体、传感器流量、系统白名单修改或伪装闹钟界面。

# INPUT-024 — 主操作裁切与任务管理器输入失败

基线 `6414249`，现有受管理分支/工作树。用户截图显示主操作 SVG/文本堆叠并裁切。独立 CSS 审查确认，旧的类专用 `display:grid` 胜过新的元素级 `button` flex 规则，而主题将高度固定为 38px。对同一类覆盖为水平 flex，并保留内在高度及 38px 最小值。不重新设计或修改无关样式。

用户输入事实：远程 Windows 任务管理器打开 -> 鼠标不可用；据报告键盘可用。用户用向日葵关闭任务管理器，然后重连 FarSail，鼠标恢复。尚未证明仅关闭即可恢复。不要声称这唯一证明 UIPI、几何问题或卡住的全局暂停。当前全局 InputState 在明确 FSR2/3 前同时抑制键盘/鼠标，因此持续可用的键盘无法仅用该机制解释。Microsoft SendInput 文档指出，返回数量/错误码不能识别 UIPI。

用户随后手动测试以管理员身份启动远程主机端，并报告控制可用。这支持提权窗口存在完整性边界的解释；它不能唯一确定每次早先失败的原因（重启也会重置状态）。在主机端注入输入不需要控制端提权。设置现在报告当前进程 TokenElevation 为已提权/普通/未知，并说明主机端可能需要手动以管理员身份启动才能操作提权应用。UAC/登录处理仍由受控电脑本地完成。没有添加自动提权。

写集：主按钮主题规则、原生只读前台/输入桌面/完整性检查、严格有界的主机输入恢复策略、回归定义/测试、候选版版本及本验证记录。不增加自动提权、权限绕过、UAC/安全桌面控制，也不修改生产配置、已安装进程或服务器。所有原始授权、共享、输入所有权和租约保护保持有效。

恢复策略：在输入失败前采集前台见证；对相同/未知/null/较高完整性/非输入桌面保留暂停。只有改变后稳定且已知安全的前台，才可在现有输入锁下准备清理会话拥有的输入。清理后重新检查上下文和授权，继续保留暂停。发送带当前暂停代数的有界 12 字节 FSU1 提示。查看器通过现有串行 FSI1 输入流回复 FSR4 加该代数。只有在全部较旧输入序列丢弃后的有序确认，才能在重新检查同一候选、授权、输入桌面、完整性和清理后解除主机暂停。不重放失败点击或排队手势。独立审查发现，单方面解除阻塞会把延迟的 InputOrder.pending 手势应用到新窗口；有序确认修复该边界。

前端 Promise 队列在 IPC 前还有第二道边界。每个普通 remote_input 携带入队时捕获的输入代数；原生在分配线路序列前，在 send_lock 下检查该代数和当前非阻塞状态。原生恢复后才派发的旧 JS 任务静默丢弃。前端状态轮询在每个较新代数上使本地手势失效，即使它跳过暂停状态而直接观察到恢复。FSR1/2/3 清理/手动恢复保持兼容。FSB1 模式及普通对等输入线路格式不变；混合版本端仍保留手动恢复，自动恢复需要两端都更新。查看器确认是独立有界任务，因此等待输入队列不会阻塞媒体 ACK 接收。

前台在现有接收循环中采样，准备探测最多每秒两次，提示每秒一次；确认执行自身必需检查。不为添加计时器而取消任何接收 future。变化/null 样本在限频前使稳定性失效。Token/进程句柄关闭，GetThreadDesktop 借用句柄保留，token 标签缓冲区有界且经过检查。只读 API 不能证明下一次 SendInput 会成功。后续真实拒绝仍暂停，并可启动新的恢复阶段。几何清理失败也会进入可恢复状态。

先前禁止浏览器自动化的指令持续有效。用户提供截图是缺陷的视觉证据，不是修正后渲染的证明。可以运行单元/原生 API 读取检查及构建；不执行浏览器、原生交互夹具或实际桌面输入。用户的管理员主机端测试是现有版本证据；新自动恢复策略尚未在实体端上执行。

An independent review caught that unilateral unblocking would apply delayed InputOrder.pending gestures to the new window; ordered acknowledgment fixes that boundary.

The frontend Promise queue has a second boundary before IPC. Each ordinary remote_input carries the input generation captured when enqueued; native checks that generation and the current nonblocked state under send_lock before assigning a wire sequence. An old JS task dispatched after native recovery is silently discarded. Frontend status polling invalidates local gestures on every newer generation even when it skips the paused state and directly observes recovery. FSR1/2/3 cleanup/manual recovery remain compatible.

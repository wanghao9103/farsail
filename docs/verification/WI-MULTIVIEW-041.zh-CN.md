# 一台控制端连接四、五台安卓目标

日期：2026-11-05。产品基线：桌面 0.1.36 / 安卓 0.1.12。证据：`.local/four-five-phones-20261105/`。

## 结果

四路、五路均通过不同账号和全部设备同账号两种场景。一台真实 NativeClient 控制端通过本地 HTTP 协调服务、隔离的 PostgreSQL schema 和真实认证加密 QUIC，连接四 / 五个独立安卓协议模拟目标。每路收发 64 KiB 媒体包与带路由标记的控制包，持续约 81 秒并跨越租约轮换。重启、最后关闭其中一路后，其余会话保持连接，额外重连为零。同账号四 / 五路分别交换 2,732 / 3,290 个包，媒体总量 179,044,352 / 215,613,440 字节。报告：`fanout-4-same-account.json`、`fanout-5-same-account.json`；不同账号报告无后缀。

Chromium 标签用例分别通过 60 次切换和仅 A 路的六次恢复，同时让 B 路状态查询延迟 1,800 ms；每会话最大在途状态查询为一，输入没有串设备。四 / 五个独立可见窗口也通过：故意阻塞 A 的解码不会停止其他窗口，A 的重连和关闭不会影响其余设备，标记输入仅到指定目标。报告位于 `4/`、`5/` 的 `tabs-result.json`、`windows-result.json`。

原协调服务集成和新增不同账号用例一起运行，3 项通过；同账号用例另行一起运行，2 项通过。客户端集成 Clippy 禁止警告、工作区格式与 diff 检查通过。

## 边界

安卓设备元数据、媒体内容和前端 IPC 为模拟。真实协调服务 / 传输与真实前端渲染分开验证，不等于五台实体手机端到端验收；没有测量安卓采集、实体解码 / GPU / 温度、游戏帧率、跨网或整夜保活。浏览器夹具约 6.4 帧 / 秒由 150 ms 合成源间隔决定，不能当作真机性能。没有使用生产协调服务或真实系统输入。

可复用原生测试位于 `crates/client/tests/coordinator_flow.rs`，需要 `FARSAIL_TEST_DATABASE_URL`，可通过 `FARSAIL_FANOUT_REPORT_DIR` 输出 JSON。未设置数据库时明确跳过执行。参见[查看器行为](WI-VIEWER-TABS-039.zh-CN.md)。

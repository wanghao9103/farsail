# WI-TASK-MANAGER-048 — 远端任务管理器启动

用户明确反馈“点击打开任务管理器后没有出现窗口”。0.1.45 仅发送六个 Ctrl+Shift+Esc 按键事件；合成界面测试只能证明顺序，不能证明系统进程或窗口启动。本次改成固定的被控端动作。

交互式桌面主进程通过 GetSystemDirectoryW 定位 Taskmgr.exe，不使用 shell、参数或调用方提供的路径。它在已登录调用者会话执行，不在 SYSTEM 代理内启动。成功条件是存在可见顶层窗口，所属进程镜像匹配系统任务管理器且会话匹配当前调用者。已有窗口直接复用、最小化时恢复，并尝试前置；Windows 可拒绝前置，因此回执证明可见窗口而非保证焦点。

动作复用已授权的有序控制通道，只接受控制权限会话；被控端先释放已有按键。通过能力协商明确拒绝旧版被控端，通过请求编号匹配回执，避免旧回复完成新请求。控制端与被控端各限制一个未完成动作，窗口确认最多八秒，回执最多十二秒。按钮展示进行中状态并显示失败原因。未增加通用命令执行、系统策略修改或 SYSTEM 进程启动接口。

## 证据与边界

源 `cbc03d4` 的 Windows 专项工作流 42781552945 已通过真实任务管理器窗口创建、已有窗口复用和系统服务采集检查。测试限定云端一次性交互 Windows runner，启动前确认没有任务管理器，再清理测试实例。本地 Windows GNU 交叉编译与 Clippy、前端类型检查及十一项跨平台 Windows crate 测试通过。最终发布源码的安装包验证完成后补充记录。

这证明云端 Windows 的启动辅助函数可用。用户实体机器上的任务管理器操作、系统策略限制、UAC 同意或拒绝、锁屏/RDP 桌面及其他系统工具仍需分别验证。

# MOUSE-022 — 键盘正常但只有鼠标失败

基线：`f7d7ddb`（已发布的 0.1.11），隔离分支/工作树。据报告，两端均运行 0.1.11；键盘仍正常，而所有桌面鼠标控制均失败。实体环境中的原因尚未确定。不要将任务管理器或 UIPI 视为已证实的原因。

写集：原生桌面远程/查看器运行时、查看器前端、聚焦的远程查看器回归、Tauri 候选版本 0.1.12、本记录。依赖不变。任务本地 node_modules/.local 输出；现有主检出 Rust target 仅作为构建缓存。不修改生产配置、已安装进程、凭据、服务器或主检出进行中工作。

已确认缺陷：画质变化时重建采集会无条件清除物理显示元数据并递增鼠标布局纪元，尽管归一化鼠标坐标仍指向同一物理显示器。修正前回归失败（`102 != 101`）。对于相同 Display，采集激活现在保留纪元和有效几何信息。选择/恢复先使几何信息失效；实际 Display 变化时推进纪元。配置变化仍重建 JPEG 采集管线，但不使鼠标坐标失效。

持续的有效坐标几何失败（至少 3 次，且持续至少 500ms）会自动释放会话拥有的输入，并重建选定采集/布局。每段连续失败只刷新一次，各失败段之间有 30s 冷却；鼠标定位成功后重新启用恢复。错误显示器、越界/非有限坐标和键盘消息不能触发刷新。Button UP 不作为定位成功证据，因为不拥有的或过期 UP 可能有意仅为释放所跟踪按钮而返回成功。不重放旧点击。清理失败通过现有 FSB1 路径暂停输入。独立的 13 字节 FSG1 反馈保留与原始输入暂停模式的兼容性，且不会仅因 Geometry 而禁用键盘/媒体。“更多操作”中的明确鼠标恢复仍作为后备方案。

连接尝试失败 3 次后，查看器显示“重新尝试连接”。手动恢复通过全新请求/批准/授权启动新的 3 次尝试周期，不把已撤销的中间请求当作原始失败会话继续查询。恢复成功后，后续独立网络故障可获得新的自动预算。拒绝/撤销、明确停止、身份变化和目标不可用保留现有终止检查；关闭会取消待处理恢复。模拟 UI 验证预算耗尽/手动/已恢复/授权结束状态。

验证：有界且考虑顺序的鼠标反馈测试、物理采集布局不变量、自动刷新/冷却和恢复授权门禁；模拟浏览器拒绝/恢复/键盘/媒体及现有指针/只读/取消回归；前端构建、desktop/Windows/media Rust 测试、fmt 和 Clippy。不得将模拟/回环证据描述为实体双机验证。没有权限变化或旧授权复用。

最终源码检查：两套浏览器测试和生产 TypeScript/Vite 构建通过。Desktop 13 项、media 5 项、Windows 13 项普通测试通过（总计 31 项）；2 项交互式 Windows 检查仍有意忽略。Desktop Clippy `-D warnings`、fmt 和 diff 检查通过。最终 desktop 运行包括 Button UP 不能清除几何失败以及自动刷新冷却的细化。尚未公开发布，也未进行真实安装。在最后一次源码细化后重复本地 0.1.12 NSIS 打包，确保交付二进制不是来自较早的进行中构建。

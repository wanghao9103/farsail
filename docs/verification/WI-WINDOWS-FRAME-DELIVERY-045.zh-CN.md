# Windows 多开传帧与授权续期重试

2026-11-07。本次分开测量原生收帧、电脑内部传帧、JPEG 解码及手机/网络性能。用户五路直连均能显示，但桌面日志捕获到一次 `renewal_failed` 关闭。旧日志未记录底层 HTTP 状态，不能据此断言具体服务端故障。

在一台 Windows 电脑上，隔离的原生 WebView2 测试使用持续 30 FPS 时钟生成 1088×502 全色彩 JPEG。原图片显示方式单窗口提交约 30 FPS，五窗口同时运行时每路约 15 FPS。随后普通 IPC 采样约为每路 11–12 FPS，电脑内部取帧耗时中位数约 60 毫秒。其他应用及用户原有远程窗口仍在运行，因此数字只对应该负载，不是独占硬件基准。提交指更新已解码图片来源，不代表显示器实际绘制或手机到电脑端到端时延。

只换 Canvas，以及配合 ImageBitmap 的实验，都没有改善该负载，相关产品代码已撤回。保留的实现继续使用原图片显示方式，Windows 帧数据改用 WebView2 只读共享缓冲。初始请求及异步等帧后的交付都会检查窗口/会话归属。每个查看器只有一个未完成读取，按请求及会话匹配接收，并明确处理取消与内存释放。原生映射投递后立即关闭，脚本映射在帧消费后释放；未知、过期、已取消的事件会释放本模块所属缓冲。不支持该接口或交付缺失时回退原二进制 IPC。认证与媒体协议没有新增。参见 [Microsoft 共享缓冲生命周期约定](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2sharedbuffer)。

首次共享缓冲五窗口观察，每路提交 21.90–23.74 FPS，内部取帧中位数 19.3–20.8 毫秒。最终同一程序对照中，强制普通 IPC 为每路 10.95–11.50 FPS（取帧中位数 66.0–69.1 毫秒），共享交付为 20.30–21.50 FPS（19.0–21.5 毫秒）。故意把第一路解码延迟 200 毫秒后，仅该路降为 4.05 FPS，另外四路仍为 25.15–26.15 FPS。共享报告均确认使用共享交付。这消除了一个实测的桌面瓶颈，但不能证明五台真实手机已达到该帧率；安卓采集间隔及无线 JPEG 容量仍是独立限制。

本地传帧读取测试覆盖跨会话匹配、多查看器隔离、取消后晚到事件、准确释放、不支持与空帧、授权错误及缺失响应后的有界回退。原生测试使用隔离配置及合成像素，显式 Debug 专用构建选项使用普通权限测试清单，正式版权限不变。

原续期代码把所有 HTTP/网络错误视为拒绝，并在首次检查失败时结束主机会话。现在将临时协调服务/网络故障与身份、权限及无效证明拒绝分开。错误 HTTP 状态会直接保留，无需读取未使用的网关错误页；成功授权证明继续保留大小限制。重试仅使用现有已验证期限，失败不延长期限；已生成令牌保留到对端确认，临时对端检查失败可请求重试。明确拒绝及独立到期门禁继续终止连接。正常连接兼容旧客户端；完整的临时故障处理需要双方更新。

五个真实 QUIC 会话注入临时检查、令牌申请及对端检查失败后，原连接保持，无需重连；持续故障测试在最后已验证期限结束，未延长期限。本地完整客户端 58 项、传输 22 项测试通过，包含撤销、身份及到期情况；桌面 68 项、前端策略/传帧读取 36 项、完整浏览器回归及原生窗口/会话隔离检查也通过。安卓首页/共享页还包含独立名称显示修改，按本机编号读取注册名称及短编号。

候选标记为 Windows `0.1.43-rc.1`、安卓 `0.1.14-lease1`。安装后的真实五手机验收仍待完成。本次工作不修改正式更新通道及协调服务部署。

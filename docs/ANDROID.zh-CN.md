# 安卓 App 预览

原生安卓 App 可以控制电脑或另一台安卓手机，也可共享本机屏幕，让 FarSail 电脑或手机控制端连接。手机版通过仓库的 Android 预览发行通道发布。复用现有协调服务、Ed25519 设备身份、逐次批准、iroh 加密传输、JPEG 画面及短期授权租约，无需修改协调服务数据库结构。

## 安装和连接

当前公开版本为 [0.1.17](https://github.com/wanghao9103/farsail/releases/tag/android-v0.1.17)：首页负责设备发现与连接，“共享这台手机”位于设置中。新增独立设备心跳，避免慢业务请求导致间歇离线；保留 Android 10 已批准控制连接的唤醒和静止屏幕首帧修复；电脑端同步更新至 0.1.45 可获得完整查看器改动。系统撤销录屏后仍需在手机重新确认；OPPO/ColorOS 真机验收仍待完成。

使用手机版前，需要用本轮源码升级协调服务：旧协调服务虽然识别安卓设备身份，但在线屏幕共享只允许 Windows，会用 HTTP 409 拒绝安卓开启共享。本次允许 Windows 和 Android 被控端，保留心跳代次、设备在线和批准检查，无需新增数据库迁移。本轮不会自动部署生产服务器。

从 Android 发行页面或本地构建安装 APK。最低支持 Android 8，APK 包含 ARM64 和 x86_64 原生库，不包含旧的纯 32 位手机。

- 在“设置 → 服务器设置”保存与电脑端相同的 HTTPS 地址，再返回登录。登录、注册、邮箱验证均为独立页面；验证码页只处理邮箱与验证码。登录后添加这台手机。
- 允许其他设备查看本机时，进入“设置 → 共享这台手机”，点击“开启屏幕共享”，确认 Android 系统录屏授权。请求共享整个屏幕，让远程触摸坐标对应真实屏幕。
- 允许其他设备控制本机时，在同一设置页点击“允许同账号设备直接控制”。尚未授权时优先打开 FarSail 详情，系统限制直达时定位到「FarSail 远程控制」；确认系统开关后返回 App，继续完成开启。仅在系统启用辅助功能不会自动授予连接。
- 开启控制后，同账号设备的查看或控制请求自动批准；其他账号仍由手机逐次确认。关闭控制、停止共享或辅助服务断开立即取消自动批准。两端均显示连接核对码。
- 鼠标点击对应轻触，拖动在松开后对应有时限的滑动，滚轮用于滚动。右键和 Escape 对应返回。更新后的电脑工具栏提供返回、主屏幕和最近任务。可向当前聚焦的普通可编辑输入框发送 Unicode 文字。
- 电脑可同时打开不同手机或电脑的查看窗口。各窗口的画面、输入、重连和关闭状态独立。现有原生客户端上限为十六个传输会话；每台手机同一时间接受一个查看端。

通过“设置 → 共享这台手机”或通知中的“停止共享”停止采集，并立即使排队输入失效。Android 已经接受的手势可能在最长 1.5 秒的限定时间内完成。密码框、任意桌面快捷键、多点触控、声音和手机文件传输不在本次预览范围。

“共享这台手机”子页分别显示未开启、等待系统授权、正在开启、共享中和失败；只有服务器接受共享后才显示共享中。失败原因保留在共享卡片，服务清理回调不会覆盖；旧服务器拒绝 Android 的 HTTP 409 需要使用 [安卓服务端升级包](https://github.com/wanghao9103/farsail/releases/tag/coordinator-android-026491f)。

## 从手机控制其他设备

登录并添加本机后，首页直接显示“我的设备”，从列表选择目标设备。其他设备在线并开启屏幕共享时，可选择控制或仅查看。作为控制端的手机不需要录屏授权或辅助功能权限，这些权限属于被控设备；对方原有同账号自动批准选择和单次连接权限继续有效。新增控制端功能无需额外升级协调服务。

远程画面等比显示。单指点击、拖动；开启滚动模式后用滑动滚动，右键或键盘入口可发送文字、回车、退格、Tab、Escape 和常用快捷键。安卓对端额外显示返回、主屏幕和最近任务。旋转画面只改变控制端图像和触控坐标映射，不改变被控设备本身方向。对方声明多显示器时可选屏。

手机控制端同一时间拥有一个前台连接。退出、切到后台、取消或登出会关闭连接并使排队输入失效；结束后须主动重新连接。仅查看连接不发送输入。画面使用最新值槽；输入有界、按序，并检查显示布局、有效租约及当前输入代次。本机屏幕共享和主动控制复用认证端点，采集权限保持独立；停止本机共享不会结束主动控制。

## 后台运行

切换应用、按主屏幕键或移除 Activity 任务后，显式启动的录屏前台服务继续运行。服务持有采集、传输状态轮询及 CPU 部分唤醒锁。Android 13 及以上不主动申请通知权限：未授权时，前台服务仍显示在系统任务管理器中，但通知栏不显示这条通知。可按需在系统设置开启通知。系统通知保持静默，没有声音或震动，停止共享后消失。Android 要求持续后台录屏使用前台服务通知；App 不隐藏该通知，也不通过开机广播重新开启采集。

部分厂商会限制后台活动。“后台运行设置”可打开应用设置，由用户允许后台运行。强行停止、收回录屏权限、进程结束以及系统锁屏行为可能停止共享。进程结束后不复用旧授权，需要重新打开 App 确认录屏。辅助功能断开会关闭控制连接，仅查看可继续。

平台要求见：[录屏](https://developer.android.com/media/grow/media-projection)、[前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types)、[通知权限](https://developer.android.com/develop/ui/compose/notifications/notification-permission)、[辅助功能服务](https://developer.android.com/guide/topics/ui/accessibility/service)。

## 构建和验证

使用 Rust 1.93、JDK 17 或更新版本、Android SDK 35、NDK 27.2.12479018 和仓库内的 Gradle wrapper。按本机路径设置 SDK/JDK 环境变量：

```sh
export JAVA_HOME=/path/to/jdk
export ANDROID_HOME=/path/to/android-sdk
rustup target add aarch64-linux-android x86_64-linux-android
scripts/build-android.sh
```

输出为 `apps/android/app/build/outputs/apk/debug/app-debug.apk`，使用本机 Android 调试密钥签名。这是可安装的测试包。正式预览包通过 `android-release.yml` 构建，使用首次安装的同一证书，关闭调试标志；证书必须保留以支持覆盖升级。脚本为原生库配置 16 KB ELF 对齐，并运行 Android lint 与 JVM 测试。缺少任一原生 ABI 时 Gradle 拒绝打包。参见 [Android 页大小要求](https://developer.android.com/guide/practices/page-sizes)。

```sh
cargo test -p farsail-android
cargo clippy -p farsail-android --all-targets -- -D warnings
cd apps/android
./gradlew connectedDebugAndroidTest
```

验证真实进程重启时，构建 debug APK 与测试 APK 后，在专用模拟器执行 `ANDROID_SERIAL=emulator-5554 python3 scripts/test-android-memory.py`。使用本地合成协调服务与相同证书覆盖安装，检查新进程、可见的新系统授权、控制保留、取消、主动停止以及旧结果 / 异设备拒绝。受 shell 权限保护的状态探针仅存在于 debug 构建，拒绝实体手机；发布工具拒绝含此 provider 的正式包。

设备测试只在专用模拟器运行，实体手机会跳过，避免改动真实账号状态。需要完整模拟器媒体/输入探针时，启动 API 35 模拟器并构建两份 debug APK，再从仓库根目录执行：

```sh
cargo build -p farsail-android --example device_probe
(cd apps/android && ./gradlew :app:assembleDebugAndroidTest)
python3 scripts/test-android-emulator.py
```

脚本清除专用模拟器 App 的合成测试数据，可见地确认系统录屏授权，并检查完整 JPEG 解码及真实鼠标/文字输入。不要用于实体手机。

主机测试使用真实本地加密 QUIC 连接验证两台手机会话互相独立、画面 ACK、有序输入、仅查看拒绝控制、旧布局及已取消的采集开启操作。设备测试使用合成本地协调服务响应，以及真实 Keystore/JNI/录屏前台服务。可选的 `realPeer` 设备测试通过模拟器 UDP 转发连接主机探针，向自建测试输入框发送文字。以上不证明实体手机兼容性、生产账号协调或跨网中继行为。结果与缺口记录在[实现验证](verification/WI-ANDROID-001.zh-CN.md)。

## 设备在线与屏幕共享

登录并添加本机后，默认开启“设置 → 保持本机在线”。独立的设备连接前台服务保持认证端点并每 15 秒续期在线状态，通知显示设备连接状态；录屏停止、手机锁屏或关闭共享页面不会自动关闭该服务。未共享时会清理过期的屏幕能力，其他设备可看到本机在线，但查看和控制仍需已授权且实际运行的屏幕共享；截图方式使用辅助功能授权。

关闭该设置或点击通知中的“停止后台在线”可停止待机；正在共享时仍由共享服务维持必要连接。退出登录、服务器或绑定设备变化会停止旧身份的在线任务。服务只保存非秘密的服务器 / 设备范围，系统重建时须重新核对原生登录与设备凭据，不保存或复用录屏授权。在线服务只持有有界续期的 CPU 唤醒锁，不唤醒显示器或解锁手机，可能增加耗电。强行停止、厂商后台策略或断网仍可能影响在线状态，可通过“后台运行”入口检查系统设置。

主界面的“允许锁屏后保持在线 · 一次性设置”和设置页的“后台在线设置”会打开系统电池优化授权，由用户决定是否允许。返回后读取系统实际豁免状态，不自动同意或反复弹出。厂商仍可能另有限制；已允许后可从同一入口打开应用信息，检查后台活动与自启动。

## 免重复确认共享（Android 11 以上）

开发版可在首页点击“启用免重复确认共享”，阅读说明后选择“启用并共享”。也可在“设置 → 共享这台手机”切换共享方式。该可选方式使用系统辅助功能截图，需在系统设置中一次性允许 FarSail 远程控制服务；开启辅助功能本身不会开始共享或自动批准连接。同账号自动控制仍需独立开启控制选项。

截图以 350 毫秒为目标采集间隔（约每秒 2–3 帧，系统限流时自动降低频率），保留画面比例与旋转，并在通知中提供停止入口。熄屏时，已批准控制者的首次点击用于唤醒屏幕并被消耗，再次点击才操作画面；唤醒不会解除密码锁。选用后返回 App 可按保存的共享选择恢复，无需新的录屏弹窗；主动停止或退出登录后不会自动恢复。权限失效会立即撤销本地能力并停止截图；恢复实际权限后返回 App 可重试。选择按当前服务器和绑定设备保存，不传给其他账号或身份。

此方式不依赖 MediaProjection，测试机上可跨熄屏 / 安全锁屏继续取得画面；真实厂商系统仍需单独验证。系统保护页面可能黑屏，不绕过密码或 FLAG_SECURE。厂商停止应用、网络限制和后台省电仍可能影响连接；不保证仅凭启用该方式就解决所有后台掉线。Android 8–10 继续使用系统录屏；所有版本均可在停止共享后切回系统录屏。

## 自动熄屏与手动锁屏

主动开启共享后，“共享期间防止自动熄屏”默认开启。允许变暗的屏幕唤醒锁由录屏前台服务管理，因此切到其他应用也生效；关闭开关立即释放，停止或失败时同样释放。不会唤醒或解锁手机。屏幕与 CPU 唤醒锁最长八小时。保持屏幕开启会增加耗电。

使用系统录屏时，手动锁屏不同于切换应用。Android 15 QPR1 及以上锁屏会结束 MediaProjection，旧录屏授权不能复用，也不能静默恢复。App 按当前登录的服务器和绑定设备记住控制与共享选择；共享仍在后台运行时直接保持状态。如果录屏已结束，回到 App 前台的主页、设置、共享或更新页会自动请求新的系统授权，无需再次点击“开启屏幕共享”；上次启动失败也可在下次进入时重试。每次进入最多请求一次，不保存录屏授权数据。登录恢复、忙碌操作或页面切换不会提前消耗这次尝试，授权引导和服务器修改页不会被弹窗打断。可在“设置 → 共享这台手机 → 打开 App 时恢复上次共享”关闭此弹窗。仅解锁进入其他应用不会开启录屏。

控制选择只在认证设备恢复成功且辅助功能服务实际连接后应用；保存开关不代表系统权限已生效，不会自行开启辅助功能系统设置。App / 通知中的停止、取消录屏授权和退出登录会撤销相应的保存意图；系统结束录屏时保留选择，等待下次前台确认。迟到录屏结果与排队控制恢复同时检查意图代次和服务器 / 设备身份。旧版系统的熄屏行为由系统决定；不会仅因屏幕关闭而主动结束仍有效的录屏。

远程控制开关显示当前实际状态：保存选择、系统授权、服务连接和本次控制能力须同时有效。权限被关闭时立即停止控制及同账号自动批准，界面明确显示系统授权关闭或服务未连接，并保留原选择；可以重新开启开关恢复授权，或用“取消已记住的控制设置”彻底关闭。系统授权与服务恢复后自动应用原选择，无需再拨一次开关。只有屏幕共享和控制均有效时才显示同账号免确认已生效；控制请求缺少权限时显示“恢复控制权限”，避免让用户反复点击无法成功的“允许连接”。

自 0.1.8 起，点击允许控制或授权引导页的开启按钮，会先记住选择，再打开系统辅助功能设置；即使授权期间进程被替换，仍保留开启选择，等待服务实际连接。共享选择在请求系统录屏授权前保存；成功返回的授权只在 Activity 内等待已认证账号状态恢复，主动停止或身份变化后仍会拒绝迟到结果。共享子页区分“共享待恢复 · 设置已记住”和实际录屏中；自动恢复请求会进入该子页显示授权状态。旧版从未成功保存的选择，升级后需明确开启一次。

参考：[Android 录屏生命周期与锁屏停止](https://developer.android.com/media/grow/media-projection)、[PowerManager 允许变暗的屏幕唤醒锁](https://developer.android.com/reference/android/os/PowerManager#SCREEN_DIM_WAKE_LOCK)。后者对普通 Activity 已弃用，推荐窗口标志；本服务需要覆盖跨应用后台共享，并负责显式释放。

## 软件更新

“设置 → 软件更新”独立管理检查、下载和安装。默认自动检查，每六小时最多一次；自动下载默认关闭，可自行开启。下载完成后仍需点击安装，并在 Android 系统安装器确认。共享期间先停止共享再安装。Android 8 以上首次安装更新需要在系统设置允许 FarSail 安装应用。

更新清单与账号服务器分离，固定来自仓库 `android-updates/latest.json`。Rust 验证内置 Ed25519 公钥签名及递增版本号；下载还检查大小、SHA-256、包名、版本与已安装 APK 的证书。密钥保存在仓库 Actions secrets；私钥和原始 APK 密钥库不得提交。版本 APK 位于不可变的 `android-v<version>` 发行页。构建与发布分为两个 job，发布重试复用已签名附件，避免重编译覆盖同版本。

本地签名构建设置 `ANDROID_KEYSTORE_PATH`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS` 后运行 `scripts/build-android.sh :app:assembleRelease :app:lintRelease`。发布前须核对 `apps/android/version.json`、APK 证书及源码标签；`scripts/configure-android-updates.mjs` 默认仅核验密钥匹配，`--apply` 配置仓库 secrets。不要轮换首次安装证书而要求用户卸载丢失数据。

如果 Actions token 创建发行入口返回 HTTP 403，保留成功的签名 artifact，通过已有发布权限创建版本与通道入口后，仅重试失败 publish；不要重新构建或覆盖版本附件，也不要为此复制个人令牌到仓库 secrets。

## 代码边界

`apps/android` 包含原生 Kotlin 界面、Android Keystore AES-GCM 存储、录屏前台服务和辅助功能输入适配。凭据保留在由不可导出 Android Keystore 密钥保护的原生存储中，禁用备份。录屏服务不对外导出，辅助功能服务由系统绑定权限保护。

`crates/android` 提供 JNI 桥接及主机运行时，复用 FarSail 的客户端、传输和媒体 crate。在 Android 执行排队操作前，再检查采集代次、布局版本和有效会话租约。画面使用最新值槽、最多两帧在途、ACK 时限及流量预算。本机停止优先于迟到的服务端响应。经过认证的对端消息标识安卓导航能力；旧电脑端仍能接收基础画面和输入，只是不显示新增导航按钮。

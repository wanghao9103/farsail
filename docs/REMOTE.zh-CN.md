# FarSail Windows 远程查看与输入（WI-004）

以下描述客户端 0.1.23 起的行为；旧版 0.1.22 不含统一远程开关。Windows 被控端必须登录、绑定设备、启动认证传输，再在本机开启“允许远程连接”。开启时实际探测当前显示器的 DXGI duplication，随后以当前心跳代次向协调服务更新 `can_host=true`；首次绑定保持 false。同一开关也在原生文件处理可用时开启文件能力；Ubuntu 使用该开关时仅允许文件连接，不提供屏幕被控。默认每条请求仍需被控端明确批准；本机已开启共享时可显式开启“远程值守”，自动批准经服务端核验的同账号查看/控制请求。0.1.10 将这两个本机选择加密保存；普通重启后重新验证同一服务、账号、设备、登录会话、心跳、传输及交互桌面，先恢复共享再恢复值守。手动关闭值守恢复逐次批准，手动关闭远程连接同时记住两项关闭，并停止本机接入的屏幕与文件连接；退出登录、身份变化清除偏好。明确退出应用或临时故障停止有效活动但保留有效偏好。关闭主窗口不停止远程访问，托盘可用时隐藏到托盘，否则最小化；从托盘或侧栏选择“退出 FarSail”才关闭应用。申请端再连接，`view` 只收画面，`control` 才可发系统输入。本机“立即停止”、断开、查看窗口关闭、应用退出、登出和租约失效都会先停止本地流与输入，再尽力撤销服务端授权。

<a id="media-contract"></a>

## 媒体契约

当前源码的画面链路仍是 **JPEG 基线**，支持 720p、1080p、2K 与 4K 档位，不放大源画面。单帧最多 4 MB，像素预算为 8,294,400；720p/1080p 仍限制在 1 MB 内。`crates/windows` 按目标显示器查找 DXGI 所属适配器，复用匹配描述的 D3D11 staging texture，处理 row pitch、DXGI rotation、负坐标与 per-monitor DPI。只复制内存，不把实际桌面帧写入文件或日志。`ACCESS_LOST`、安全桌面或模式变化仍按既有恢复流程处理。

`crates/media` 的 `FSM1` 二进制包为：四字节 magic、字节 codec=1（JPEG）、`u32 monitor`、`u64 layout`、`u64 sequence`、`u64 captured_ms`、`u32 width/height`、`i32 origin_x/y`，均为大端，接着是 JPEG。解码前检查长度、像素预算及 JPEG 自身的尺寸，不能仅相信声明的宽高。显示器列表是 `FSL1` 后跟 JSON；查看方通过 `FSS1`+大端 `u32` 选择显示器。切屏重建采集并递增 layout，旧画面的鼠标坐标被拒绝。画面按实际收到的帧计 FPS，网络 RTT 是所选 QUIC 路径的 RTT，不等于画面延迟。H.264/H.265、4:4:4 和自适应码率留给 WI-006。

当前源码以 30 FPS 为采集调度目标，把采集和编码时间计入每帧间隔，不在处理完后固定追加 66 ms；这不是实际远程帧率保证。编码库在支持的 x86 CPU 上运行时选择 AVX2 路径，其他 CPU 保留普通路径。采集线程只保留一个最新帧槽，DXGI 无新内容或 RGB 相同则不重复编码，静止画面约每秒更新一次缓存帧。发送端最多两帧在途，窗口满时等待累计 `FSA1` 序号确认，恢复后取最新帧，不积压中间 JPEG；乱序旧 ACK 不回退进度，未发送序号的 ACK 会关闭会话。ACK 期限为 2 秒，高档位为 5 秒，连续三次无进展才以媒体超时停止；即使采集不再更新，未确认帧也会到期。媒体读写保留按包大小计算的有限期限，部分帧超时/reset 后继续读下一条。JPEG payload 预算为 6 MB/s，等待预算后重新取最新帧；HD 帧龄超过 700 ms、高档位超过 2 秒则丢弃。预算不含 QUIC/TLS/IP 首部和重传字节。控制接收与媒体发送分别运行。

编码性能可用 `cargo run --release -p farsail-media --example encode-bench` 在纯合成像素上比较；结果只衡量单机 JPEG 编码，不代替双机游戏、GPU 采集或公网帧率验收。

<a id="input-and-permissions"></a>

## 输入与权限

原生层解析白名单 `Input`：归一化坐标移动、带显示器/布局/坐标的左或右键、双向滚轮、允许的 Windows VK 按下/抬起与最长 64 字符的 Unicode 文本。viewer 先按实际图片适应窗口计算留黑区域，只向图片内发送 0–1 坐标。系统映射到该显示器的物理像素，保留负坐标；按钮/滚轮自行验证并移动到所带位置，不依赖先前的 move 消息。中键、非有限/越界坐标、过期布局、额外 JSON 字段、未知 VK、过大消息被拒绝。

每条控制消息有连续序号；本地发送由有界锁和队列串行，鼠标移动繁忙时可丢弃。主机可暂存 32 条乱序输入，等待缺失序号最多 2 秒，重复、过大缺口、持续缺失或总量超限会关闭会话并释放按键；高频移动超过每秒 120 条时只丢移动，不丢按键抬起或释放命令。执行输入前在持有同一个输入锁时再次检查本机共享开关、会话状态与当前布局。停止先清活动标志，随后持锁释放本会话已注入的键和鼠标按钮；`SendInput` 释放失败会重试并报告清理未完成。viewer 失焦、指针离开画面及“释放按键”会送释放命令。Windows 客户端 0.1.23 起在应用启动时通过正常系统 UAC 提示申请管理员权限；0.1.22 不含该策略。不绕过 Windows 授权或游戏输入过滤。安全桌面、UAC 提示和无人登录桌面仍不支持远程控制，须在被控电脑本地处理。见 [Windows 启动说明](WINDOWS_INSTALL.zh-CN.md)。

双方校验码使用同一 QUIC/TLS 连接的 exporter，以 `farsail/verify/v1` 和会话 ID、精确权限、双端设备公钥作上下文导出，再显示短码供人工比较。grant、设备 token、私钥和刷新凭据仍只在 Rust。页面收到的二进制帧经 Tauri raw IPC、Blob JPEG 渲染，不把桌面帧放入日志或长期存储。

<a id="local-execution-and-acceptance"></a>

## 本地运行与验收

0.1.11补充：显示/画质布局变化不应丢掉已注入按钮的UP。只有本会话拥有的按钮能释放；缺失/旧布局不阻止释放，仍不允许旧坐标的新DOWN。查看端自有指针捕获覆盖拖出后的结束，失焦或异常丢失捕获释放并取消，外面已按住再移入不会成为新的远端点击。所有执行仍在有效授权/共享/会话/输入锁检查后进行，Windows拒绝不被绕过。见 [INPUT-021](verification/WI-INPUT-021.zh-CN.md)。

先按 [客户端说明](CLIENT.zh-CN.md) 启动本项目 PostgreSQL/Mailpit、协调服务及 Tauri。双端本机集成测试用隔离账号、临时 DPAPI 目录、真实 PostgreSQL/Axum/iroh，正常流程更新主机能力；不手改数据库。`scripts/test-remote.ps1 -RealCapture` 在有交互桌面的本机额外执行真实 DXGI→JPEG→认证连接→解码，实际像素始终只在内存。`cargo test -p farsail-windows real_input_into_own_foreground_window -- --ignored --nocapture` 只在测试程序自建窗口获得并核对前台进程后发送无害文本、组合键和点击；若前台核对失败，测试在注入前失败。CI 没有交互桌面，仅运行合成帧、坐标/旋转、权限与构建测试，不能替代上述两项本机证据。

桌面配置目录通过 Windows 文件排他锁防止并发进程使用同一个刷新令牌；debug IPC 烟测可用 `FARSAIL_TEST_PROFILE_DIR` 指向独立临时目录。停止测试服务用 `scripts/test-coordinator.ps1 -Stop`，仅影响 `farsail-dev` 项目，保留数据卷和忽略的 `.local/dev.env`。公网服务、第二台 Windows、跨 NAT、移动真机及安全桌面均未在 WI-004 验证。

当前[文件基线](FILES.zh-CN.md)使用 `Session::send/receive`、`File` 通道、独立 `files` 授权和由统一远程设置控制的 `can_files` 能力。文件连接始终需要手动批准，包括已开启同账号远程值守的情况；不启动采集/输入，也不继承屏幕权限，远程开关首次默认关闭，重启后仅在验证通过时恢复。尚不支持续传。

<a id="012-separate-window-and-recovery"></a>

## 0.1.2 独立窗口与恢复

查看/控制在独立原生窗口打开，关闭窗口只结束该会话，主设备管理窗口保留。点击画面取得键盘焦点；失焦、断开或停止时取消排队输入。结束状态清除旧画面并显示中文原因。媒体/网络超时可自动尝试最多 3 次全新授权请求，随时关闭窗口取消；授权拒绝、撤销、到期和不明原因的旧版关闭保持结束状态。实际所选 P2P/relay 路径与 RTT 持续显示；路径迁移不等于重连。此版本兼容已发布服务端，不要求重部署。验证和限制见 [WI-REMOTE-012](verification/WI-REMOTE-012.zh-CN.md)。
